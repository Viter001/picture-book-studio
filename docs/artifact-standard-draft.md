# 编辑工具与交互叙事作品产物规范：讨论草案

2026-10-27。已确认：本项目交付绘本编辑工具，工具生成的产物应有统一规范。用户进一步明确用途可包括绘本、Galgame 和其他叙事作品，交付方式不限定为网页或独立程序。本文此前“阅读包”统一理解为可供阅读或游玩的“运行包”。下列格式、文件名、校验与交付方式为建议，尚未冻结，不是已实现能力。

## 1. 两层交付对象

| 对象 | 使用者 | 建议交付内容 |
| --- | --- | --- |
| 绘本编辑工具 | 作者 | 可安装的桌面程序、版本信息、使用说明、示例工程及外部 agent 接入说明 |
| 工具生成的绘本 | 作者及读者 | 可继续编辑的规范工程；需要分发时生成规范阅读包，具体载体待确定 |

编辑工具采用已确认的 Electron + React + 自有绘本模型。阅读包不因编辑工具采用 Electron 就必须再次打包成 Electron 应用。

## 2. 可编辑工程与阅读包

建议区分两个产物形态，共用一套作品内容定义：

- 可编辑工程：包括作品内容、所有使用的素材，以及流程图位置、编辑辅助设置等作者信息，能够迁移到另一台电脑继续编辑。
- 阅读包：由工程导出，包含阅读所需的内容、素材及匹配的播放器或明确的播放器版本要求，不依赖作者机器上的路径与缓存。

工程中的作品内容是编辑真相源，阅读包由导出器产生，不分别手工维护两套剧情。编辑布局等辅助信息可以不进入阅读包，但页面、连接、动画、音频以及已支持的剧情规则不得在导出中静默丢失。

建议开发阶段使用目录结构，未来可增加单文件打包。扩展名与压缩方式不在本轮确定。

## 3. 应规范的内容

| 规范面向 | 建议要求 |
| --- | --- |
| 版本与身份 | formatVersion、bookId、内容版本、所需播放器版本/能力；格式版本与软件版本分开 |
| 页面与连接 | 稳定页面/连接 ID，明确起始页、出口、分支与循环；展示页码不作为唯一身份 |
| 图层与媒体 | 图层顺序、可见性、坐标及尺寸单位；素材通过 ID 和相对路径引用 |
| 音频与动画 | 音轨类型、时长单位、播放/停止/重播规则、动作预设 ID 和参数；规则不能只存在于编辑器代码中 |
| 素材清单 | 文件类型、尺寸或时长、编码信息、大小和可选完整性摘要；无作者机器绝对路径 |
| 条件与数值 | 若采用隐藏数值系统，变量类型、初值、条件、修改效果和重复触发语义必须纳入统一格式；当前仍属待讨论 |
| 阅读状态 | 当前页、路径历史、变量当前值等作为读者存档独立保存，不改写作品初始定义 |
| 兼容与迁移 | 不支持的格式/能力明确报告；旧版本转换有迁移记录，不能悄悄删去规则 |

背景与人物音频离页行为、循环计分和回退语义等仍需产品裁决，本草案仅规定必须写清，不提前替用户决定。

## 4. 候选组织示例

以下文件名仅为示意：

可编辑工程：project.json（作品与编辑元信息）+ assets/（图片、音频、视频）+ 可重建缓存。
阅读包：manifest.json（格式/能力/文件清单）+ book.json（作品内容）+ assets/ + player/（如果该交付形式自带播放器）。

导出器从工程的作品部分生成 book.json，采用相同的核心类型和校验规则。播放端和编辑预览共用播放内核，避免同一份作品在两端出现不同剧情结果。

## 5. 验证与失败处理

保存草稿和发布检查应分开：未连完的流程允许保存，并显示待完成项；格式损坏或写入失败不能覆盖有效工程。发布前执行更严格校验：

1. 内容结构可解析，版本与能力受支持，ID 唯一且引用有效。
2. 起始页存在，素材齐全、相对路径可解析，必需格式能在目标播放器解码。
3. 分支条件与效果符合声明；合法循环不算错误，连续自动跳转循环需单独处理。
4. 不满足开放条件导致无可用出口时，依已确认的终点/兜底规则给出诊断；无法静态判定的路径须记录并做运行验证，不能承诺穷尽全部情况。
5. 编辑预览与阅读包以同一场景核对页面、音画和路径行为。
6. 将工程/阅读包复制到新目录或另一目标环境，验证不依赖原始素材位置、开发服务器或作者缓存。

建议输出可读的校验报告，标明阻断错误与非阻断提示，定位页面、连接、图层或素材。未发布不妨碍保存未完成的草稿。

## 6. 对 MVP 的影响

从 MVP 起应规范工程格式、素材引用、ID、格式版本、核心播放规则及校验器；不把产物格式拖到开发末尾补做。
独立阅读包是否也属于首版交付，尚待用户确认。此前产品规划将其放后续阶段，本轮未擅自将该建议改成已批准范围。

隐藏数值与选项条件系统是用户提出的探索方向，尚未确定采用范围；若纳入，需在正式格式设计时一起确定，不能只作为界面属性。

## 7. 多目标交付与后续决策

不要求现在选定唯一交付形式。建议工程与运行数据保持目标独立，网页、离线程序和配套播放器文件作为不同的导出目标；其能力、加载方式、存档和分发分别验证。后续只需按 MVP 验证成本决定第一个实现目标，不据此限制未来作者用途。
不把 MP4/PDF 当作完整交互绘本的等价产物；若以后需要，可作为会失去分支交互的辅助导出，另行定义范围。

## 8. 通用作品核心与导出适配（建议）

- 作品核心描述场景、媒体、图层、流程及已支持的规则，能力版本独立于 Electron 编辑工具版本。
- 共用运行时负责播放与状态变化，编辑预览和各运行包使用同一套语义。
- 导出器负责素材收集、目标能力检查及平台封装；网页包和桌面包不保证天然等价，需分别验收媒体、输入和存档。
- 发布目标可携带不同入口与存档适配，但不改变作品的分支与计分规则。
- agent 制作与人工制作使用相同产物规范；最终作品可以独立运行，实时 AI 剧情另属新需求。
- MVP 不承诺同时完成全部导出器，也不把通用游戏能力列为已批准功能。
