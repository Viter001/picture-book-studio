# 前后端职责与视觉参考讨论稿

2026-10-27。Electron + React + 自有绘本模型已选定；下列边界与视觉方向为建议。

## 1. 前后端如何理解

前端是用户直接操作的 React 窗口；后端是随桌面应用运行在本机的工程与素材服务。首版无需云端部署。播放器在前端渲染，文件和工程提交由本地服务处理。

前端管理交互状态和即时拖拽反馈，修改完成后提交命令。本地服务保留权威工程状态，校验、记录撤销并通知所有视图。外部 AI 调用同样的命令，因此用户界面与 AI 不会各自维护独立的项目副本。

建议优先讨论：工程保存方式、素材导入反馈、界面与 AI 同时编辑时的表现。代码文件和模块细分已收录到产品规划，仍可在正式设计中调整。

## 3. 三个视觉方向供比较

| 方向 | 建议特征 | 取舍 |
| --- | --- | --- |
| A：清晰的桌面创作工具（推荐） | 中性浅灰工作区、清晰边界、单一强调色，熟悉的页面与属性操作 | 上手容易，适合页面与文字编辑；媒体轨道仍需保持足够清晰 |
| B：专业媒体工作台 | 深灰界面，突出画面预览与音轨状态，信息密度较高 | 适合持续音画编辑；需要避免基础页面操作被复杂面板掩盖 |
| C：轻量绘本工作室 | 柔和浅色、较大缩略图、少量常用操作先露出 | 亲和但会占更多空间，后续丰富功能需要渐进展开 |

建议先以 A 为基线，把 B 的音轨辨识和 C 的缩略图可读性融入，不预先建设多套主题。

## 4. 信息组织建议

- 用户明确复杂非线性图与单页编辑放在同一页面会拥挤。建议改为同一工程的两个完整工作区，切换显示，不把两套编辑器常驻并排；预览是共用能力。
- 页面编辑中围绕当前页面组织图层、音频、动画；选择对象后显示对应属性，避免同时展示全部参数。
- 页面转场作用于页，元素动画作用于图层；在命名与面板中保持这个区别。
- AI 连接状态、操作记录和变更结果有清楚入口；不增加内置 AI 聊天区。
- 保存中、未保存、导入中、格式不支持、素材缺失和 AI 修改等状态需要可见。
- 用户界面优先采用“页面、图层、背景音乐、人物配音”等业务词，不直接暴露 schema、IPC 或内部命令名。

这些是待评议布局原则，尚未制作界面草图或建立视觉规范。建议下一步并排制作 A/B 两种静态工作区草图，讨论后确定风格与布局。

## 5. 复杂流程与页面编辑如何结合（新增讨论）

已确认：流程存在分支和循环；页面编辑参考 PPTist/Penpot，不能用线性缩略图顺序代替流程关系。

方案 A（推荐）：双工作区，节点进入页面编辑，返回时定位原节点并恢复缩放与平移。空间充分、上下文可恢复，适合复杂图。
方案 B：流程为主，右侧大抽屉编辑单页。适合快速改名或属性，完整图层/音画编辑仍容易挤占空间，建议仅用作轻量检查。
方案 C：流程与每页分别打开工作标签。适合频繁跨页比较，但需要管理标签、选择状态和导航；可作为方案 A 后续增强。

推荐先 A，再按需要增加 C；抽屉只用于快速查看和少量修改。用户尚未确认具体导航方案。
