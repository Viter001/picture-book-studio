# MVP 产品规划 v0.6

2026-10-27。状态：首版候选方案，未冻结、未开始功能实现。与 [全局产品设计与发展规划](product-roadmap.md)分离。

## 1. 本文的边界

本文只回答首版解决什么问题、交付哪些能力、如何验收。全局方向、架构扩展与后续发展以全局规划为准，不自动变为 MVP 任务。

用户已确定 Electron + React + 自有绘本模型路线；具体功能子集、组件和视觉仍待讨论。此前把分支、循环或更广泛用途直接写成首版必需的表述不再生效。相关产品方向保留，首版覆盖深度单独决定。

## 2. 首版目标（建议）

首先解决用户原始痛点：页面和素材只能交给 AI 导入，用户无法自己添加和组织页面。

候选最小流程：新建工程 → 导入素材 → 添加/编辑页面 → 组织基础连接 → 预览 → 保存 → 重开继续编辑。
首版采用绘本样本验收，不要求同时验证 Galgame、多目标发布或完整隐藏数值系统。

## 3. 候选范围及状态

以下按此前“六方向各提供基础能力”的建议保留讨论基线，不表示用户已经批准所有条目。若改为更小的页面优先版本，也在本文明确调整。

| 模块 | MVP 候选能力 | 本轮状态 |
| --- | --- | --- |
| 工程 | 新建、手动保存、重开，素材随工程管理，基础错误提示 | 建议纳入最小流程 |
| 页面 | 添加、删除、命名，图片放置，基础位置/尺寸编辑 | 建议纳入最小流程 |
| 流程 | 可视化页面连接、起点、节点定位与预览 | 具体连接规则待确认；分支/循环编辑与播放均不自动列为首版必需 |
| 图层 | 选择、显示/隐藏、基础顺序调整 | 首版候选；文字图层及细项待确认 |
| 多媒体 | 图片导入为基础；音频与视频导入/播放作为候选 | 具体类型、编码和数量上限需选择与实测 |
| 音频 | 背景/人物分类、试听、关联页面、音量 | 首版候选；不固定一页几轨或跨页行为 |
| 动画与转场 | 分开的效果列表，少量效果及基础参数 | 首版候选；效果清单与触发规则待定 |
| 外部 AI | 共用编辑命令；候选真实接通一个宿主及少量工具 | 接口边界需保留；实际接入覆盖范围待确认 |
| 预览与撤销 | 当前已支持内容的预览、基本撤销/重做 | 首版候选，行为与验收需随范围明确 |

基础对象和规则必须服务于已选功能，不能把这张候选表直接当作开发清单。

## 4. 从首版就应遵循的基础边界（建议）

- 页面与素材使用稳定 ID；连接与页面数据分开，允许以后扩展非线性规则，不以单一 nextPageId 锁死格式。
- 工程格式带版本，素材使用项目内引用，保存重开可核对；未完成流程允许作为草稿保存。
- 编辑动作通过明确命令处理，界面不成为唯一业务入口，为外部 agent 调用保留通路。
- 编辑数据、播放临时状态与未来读者存档分开；播放逻辑不绑定 Electron 文件系统 API。
- 未支持的格式或能力明确提示，不静默删除未知规则或假装已播放。

“保留通路”不等于提前实现插件系统、全部 MCP 工具、变量计算器或所有发布器。具体实现只覆盖确定的首版功能。

## 5. 不因全局讨论自动进入 MVP

| 全局方向 | 首版处理原则 |
| --- | --- |
| 完整分支、循环与复杂路径管理 | 模型保留空间；首版编辑及播放子集另定，不能假定已批准或已取消 |
| 隐藏数值、选项条件、重复计分 | 保留状态/规则边界，功能设计与实现另行立项 |
| Galgame 对话、角色与其他游戏玩法 | 保留长期用途，不列为当前首版完成条件 |
| 网页、独立游戏、配套播放器等多目标产物 | 工程规范先行，具体导出器单独分配版本 |
| 旧绘本完整导入与无损迁移 | 来源可供参考，未承诺首版兼容 |
| 完整时间轴、复杂动画、转码与丰富格式 | 按真实需求与性能验证后推进 |

## 6. 首版推进方式（候选，不是开发授权）

1. 冻结最小场景与功能子集：从第 3 节选择首版条目及基础规则。
2. 技术验证：针对已选条目验证工程读写、媒体渲染、命令调用；原型与正式功能分开记录。
3. 可编辑闭环：实现导入、页面、基础图层与保存重开。
4. 可预览闭环：实现已选连接规则、音画及预览。
5. 试用与交付：按已选范围完成桌面测试，若纳入外部 agent 则做真实接入验收。

只有所有已批准首版条目通过验收，才能声明 MVP 完成。没有批准的条目不因发展规划中出现而成为阻断项。

## 7. 候选验收

基础场景建议使用 3—5 页短绘本。选中的功能应满足：

- 用户无需手改代码即可导入图片、添加和编辑页面、组织首版支持的连接。
- 保存重开后，已支持的内容、素材与布局一致；移动原素材不破坏已导入工程。
- 当前支持的图层和播放规则在编辑/预览中一致；未支持能力得到明确反馈。
- 失败操作不破坏工程，撤销行为符合已选规则。
- 通过真实 Electron 窗口验证核心流程，记录环境和视觉检查结果。

条件验收：音视频、动画、外部 AI、分支循环或导出被选入 MVP 时，必须分别补齐样本与验收；未选入则不声称具备，也不要求首版实现。分支编辑通过不等于分支播放通过。

目前所有功能验收均未执行。

## 8. 尚需确认的首版决策

- 页面优先，还是六方向基础能力的首版组合。
- 基础连接编辑与播放的范围，是否包含简单分支或回连。
- 音视频、文字、效果的最小集合；音轨与图层的具体行为。
- 外部 agent 的最小真实接入范围。
- 是否需要独立运行产物，或首版先以工程保存和内置预览交付。

这些决策在进入实施前确认，不妨碍先继续讨论全局设计。基础对象暂沿用页面/节点，不要求现在确定“场景”命名。
