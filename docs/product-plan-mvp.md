## 1. 产品定位

面向绘本创作者的可视化制作工具：用户可以自行导入素材、组织页面和页面之间的流程、配置音频与动画，并通过图层控制展示内容。
同时为外部 AI agent 提供工具接口，支持人和 AI 协作编辑。软件内部不内置 AI 助手。
首批目标用户建议以当前绘本项目创作者为主，先解决必须依赖 AI 才能添加页面和组织内容的问题。

## 2. MVP 的核心目标

用户无需修改代码，即可完成一部短绘本的基本制作：

新建项目 → 导入素材 → 添加和编排页面 → 配置图层、音频与动画 → 连接页面 → 预览 → 保存并再次打开。

外部 AI agent 可以读取项目并执行一组实际编辑操作，结果能被用户查看和继续编辑。
“保存”在 MVP 中指保存可继续编辑的工程；独立发布或导出最终阅读作品另列后续阶段。

## 3. 范围取舍

| 方案 | 优点 | 局限 |
| --- | --- | --- |
| 页面优先：只完成页面导入和连线 | 最快验证最初痛点，开发范围最小 | 不能验证音频、动画、图层与 AI 的协作方式 |
| 六方向各做基础能力（建议） | 能用一部短绘本验证完整制作流程，并尽早验证 AI 接口 | 首版比页面工具大，必须严格限制效果、轨道和格式范围 |

本规划按第二种方案拟定，尚未代表用户选定。MVP 的目标是每项基础能力可用，后续版本再增加深度。

## 4. MVP 功能范围（建议）

| 模块 | 首版可用能力 | 后续再扩展 |
| --- | --- | --- |
| 页面与流程 | 新增、删除、改名页面；节点对应页面；可视化连线；设置起始页；支持分支与循环连接；提示无效引用和不可达页面 | 条件表达式、对话选项、复杂变量规则 |
| 多媒体导入 | 用户选择图片、音频、视频文件导入素材库；查看素材类型、名称与预览；将图片或视频放入页面 | 批量转码、更多编码、复杂素材检索 |
| 图层 | 页面中的图片和视频作为独立图层；建议补充基础文字图层；选择、命名、显示/隐藏、调整上下顺序；基本移动和缩放 | 分组、锁定、蒙版、复杂混合效果 |
| 音频 | 区分背景音频与人物音频；可关联人物名称；每页配置一条背景与一条人物音频，设置音量、试听和移除 | 多人物同时混音、波形剪辑、精确时间轴与自动对齐 |
| 动画与转场 | 两组效果列表；页面转场先做无效果、淡入淡出；页内先做无动画、淡入；可调时长和预览 | 更多进入/退出/强调/路径效果，组合动画与触发编排 |
| 外部 AI 接口 | 实际接通至少一个外部 agent；支持读取项目、导入素材、添加页面、连接页面、设置图层可见性及保存 | 逐步覆盖全部编辑操作、批量任务和更丰富的结果反馈 |
| 工程与预览 | 新建、手动保存、重新打开工程；预览单页或全流程；基本撤销/重做；素材随项目管理 | 自动恢复、历史版本、独立阅读包与发布 |

上述数量和效果清单是用于控制首版规模的建议，不是对已确认产品方向的删减。

## 5. 必须说清的基础行为（建议，待确认）

- 用户已明确流程为非线性，包含分支与循环，取代此前单一路线建议。首版流程模型与编辑器应支持多出线、汇合及回连；分支在实际阅读时如何触发、如何选择仍待确认。编辑态的路线检查不能冒充完整阅读规则。
- 页面内图片和视频可定位、缩放及调整图层顺序；MVP 不增加绘画、修图或视频剪辑工具。
- 图层隐藏暂建议同时影响编辑画布和播放预览，避免两者表现不一致；是否还需要“仅编辑时隐藏”后续确认。
- 音频暂以页面为单位：进入页面开始播放，离开页面停止；背景可循环，人物音频播完停止。跨页背景连续播放与人物台词分段留待讨论。
- 视频首版提供基本播放与暂停；预览时视频原声默认静音，避免与背景/人物音频冲突，是否允许开启原声后续细化。
- 动画暂固定为进入页面后执行，不引入点击触发、对话触发或时间轴。浏览器或系统要求用户先交互才能播放声音时，预览入口须明确启动播放。
- 导入素材复制到项目管理范围内，避免原文件移动后工程失效；不修改用户原素材。
- 界面和 AI 使用一致的编辑规则及同一份项目状态；AI 修改可见、可撤销。最小接口应包含明确的成功或失败结果，失败不留半成品修改。
- 人与 AI 同时编辑时，需要避免静默覆盖；具体采用串行操作还是版本校验，在技术设计中确定。

这些行为直接影响体验，必须在开发前讨论确定，不能当作用户已经批准。

## 6. 格式兼容与原项目复用

主流格式兼容是已确认目标。建议首批验证样本为 PNG/JPEG/WebP 图片、MP3/WAV/M4A 音频、MP4 视频（明确视频及音频编码组合）。WebP 与 M4A 来自原绘本实际素材类型；基础文字图层也建议列入首版范围确认。这里只是候选测试集合，不是已验证兼容承诺。
具体支持格式、编码组合和尺寸限制须结合运行平台实测后公布；导入不支持或损坏的文件时应给出明确提示，并保持工程可用。

原项目 `E:/code saving/INTERACTIVE-NARRATIVE-SYSTEM/` 是复用来源。进入技术设计前，核对页面数据、素材、播放、音频与动画能力；仅复用适合编辑器的部分。已定向核对页面、DOM 渲染、音频、视频和动画模块，尚未完成适配评估，不能承诺旧工程直接导入或无损往返。
建议 MVP 先建立新工程制作流程，并使用经确认的原绘本素材进行试用；旧工程迁移列入后续版本，除非用户将其确定为首版必需。

## 7. 从 MVP 开始的版本路径

| 阶段 | 目标 | 完成标志 |
| --- | --- | --- |
| MVP-0：验证关键技术 | 在选定路线下验证媒体渲染、保存重开和最小 AI 命令，形成可复核证据 | 技术验证通过后明确兼容清单与模块契约；原型不自动等同产品功能 |
| MVP-1：可编辑工程 | 素材导入、页面、基本图层、保存重开；同步定义共用操作模型并保留最小 AI 调用贯通 | 用户能创建多页工程，重开后素材和位置一致 |
| MVP-2：可播放绘本 | 页面连接、基础音频、动画、转场和预览 | 能按连接顺序播放，音画行为符合约定 |
| MVP-3：可协作试用 | 外部 agent 实际调用、撤销与失败处理、完整流程验收 | 人与 AI 能接续编辑同一工程，真实样本通过验收 |
| v0.2：提升制作效率 | 扩展效果与格式，完善音频组织、跨页播放和素材管理 | 结合 MVP 试用反馈选择需求，不预先全部承诺 |
| v0.3：交付与兼容 | 可分发阅读成果、已有项目导入；按需求扩展条件规则与交互 | 分别明确导出和迁移验收，不把保存工程等同于发布 |

MVP-0 是开发前的技术验证；MVP-1 至 MVP-3 合起来才是本规划的首版；完成 MVP-1 不能宣称整体 MVP 已完成。时间与人力尚未估算，须待范围和技术评估确定。

## 8. MVP 验收场景（建议）

准备一部 3—5 页短绘本样本，包含多张图片、一段视频、一段背景音频和一段人物音频。

1. 用户自行导入素材、创建页面并调整布局，全程不手动改代码。
2. 建立包含分支、汇合和回连的页面图，设置起点，保存重开后连接保持。依最终确认的分支规则分别走通不同路径，并验证循环可重复进入、可退出；不可达页面得到提示，合法循环不被报错。
3. 页面中至少两个图层可以独立显示/隐藏，顺序和位置正确，重新打开后保留。
4. 背景和人物音频能清楚区分、试听与调整音量，翻页行为符合最终确认的规则。
5. 视频可以预览播放；页面转场与页内淡入可以从列表选择，效果和时长生效。
6. 保存、关闭、重新打开后，素材、页面、连线、图层、音频和动画设置保持一致；移动原始素材不破坏已导入的工程。
7. 至少一个外部 AI agent 实际读取工程、添加页面并建立连接；用户在界面看到结果、继续编辑，能够撤销该编辑操作。
8. 不支持的媒体、失败的 AI 调用或编辑冲突得到明确反馈，不损坏已有项目。

以上为未来验收标准，本次只交付规划文档，均未执行功能验收。

## 9. 下一轮需确认的决策

优先确认首版采用“六方向各做基础能力”还是“页面优先”。随后逐项确认：

- 本地工程的保存位置与组织方式（桌面 Electron 路线已确认，不再重新询问产品形态）。
- 首版是否必须打开现有绘本工程，而非仅使用其素材和能力。
- 分支选择和循环触发的播放语义，以及每页基础音轨和最少动画效果能否满足首版试用。
- 图层可见性、音频翻页行为和视频原声的约定。
- 外部 AI 首个验证对象、调用方式与共享编辑规则。

此前“登录登出”一词含义仍未确定，不据此引入账号系统或已批准的音频进出场机制。
正式设计需在这些关键取舍确认后编写；技术主路线已确认，细节设计和功能实现尚未启动。

## 10. 前后端架构规划（路线已确认，职责细分为建议）

首版采用本地应用架构，不以云服务器、账号或远程数据库作为运行前提。

| 层次 | 主要职责 | 数据边界 |
| --- | --- | --- |
| React 前端 | 页面/流程视图、素材与图层面板、属性与动画配置、播放预览、导入和保存状态反馈 | 保留选择、缩放、拖拽草稿等临时状态；作品修改提交命令 |
| Electron preload | 为前端提供明确的工程操作接口与事件订阅 | 使用 contextBridge/IPC，不暴露任意文件读写及通用执行入口 |
| 本地应用服务 | 工程打开保存、素材复制与元数据、串行编辑命令、撤销重做、版本与错误处理 | 单一工程写入者；校验完成后提交修改并通知前端 |
| 共用绘本核心 | 类型、校验、页面/图层/音频/动画规则和版本迁移 | 不依赖 React 或 Electron UI；前端可复用类型及校验提示 |
| 播放模块 | 页面渲染、媒体生命周期、动画预设与转场 | 位于 renderer，编辑和预览共用渲染能力，播放状态不写成作品内容 |
| 外部 agent 接口 | MCP 工具声明、参数校验与本地连接 | 调用同一个应用服务，不另外读写一份工程 |

Electron 主进程承载轻量命令及文件协调；耗时素材分析和未来转码放入 worker/utility process，避免拖慢窗口。此分工参考 [Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)及 [context isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)。

建议以 TypeScript 贯穿界面、契约和核心；构建工具及组件库在界面需求确认后锁定。首版无需单独部署 Web 后端或关系数据库。

## 11. 自有绘本工程模型（建议）

| 对象 | 要保存的信息 |
| --- | --- |
| Project | schemaVersion、projectId、revision、名称、起始页、画布默认尺寸 |
| Asset | 稳定 ID、类型、相对路径、尺寸/时长等元数据；格式支持状态 |
| Page | 稳定 ID、名称、图层集合、音轨引用、转场配置 |
| Layer | 稳定 ID、素材或文字内容、位置尺寸、顺序、可见性、动画配置 |
| Connection | 源页面与目标页面；节点图布局坐标独立保存 |
| AudioTrack | 背景/人物类型、素材引用、人物标签、音量与播放规则 |
| AnimationPreset | 预设 ID 与参数；工程不保存任意可执行脚本 |

工程建议为 project.json + assets/，可移动并再次打开。缓存与缩略图可重建，不作为素材真相源。使用稳定 ID，显示页码变化不破坏连线。实际 schema、迁移与格式上限待正式设计确定。

保存采用完整校验后写临时文件并替换；导入失败或命令失败不留下半完成的作品状态。撤销重做针对同一命令历史；磁盘备份与跨会话历史恢复另行规划。

## 12. 共用编辑命令与 AI 接入（建议）

界面 → preload → 本地命令服务；外部 agent → MCP bridge → 同一本地命令服务。

每次命令携带 requestId、projectId、expectedRevision 和参数。服务按顺序执行，检查引用与版本，返回对象 ID、新 revision 与结构化结果；前端通过事件更新工程视图。重复请求和过期版本需要明确处理。

基本命令：读取工程、导入素材、添加页面、连接页面、设置图层可见性、配置音频/动画、保存。首版对外开放最小集，内部模型从起步阶段就覆盖六方向，避免后补 AI 时改写业务逻辑。

桌面应用作为当前工程唯一写入者；没有打开工程时，工具给出明确状态。MCP 并不保证所有 agent 宿主自动兼容，应以实际宿主调用作为验收证据。软件中只需显示连接状态及操作结果，不内置聊天助手。

## 13. 视觉设计与使用流程（待讨论）

用户指出复杂流程图与单页编辑并排会拥挤。建议采用同一工程的两个独立完整工作区：流程视图与页面编辑视图，通过节点进入页面、通过返回流程定位原节点；保留流程缩放/位置及页面编辑状态。具体切换形式尚待确认。音频、动画与图层围绕当前页面配置。

建议以 PPTist 的页面编辑习惯作为主要交互参考，以 Penpot 的图层及属性组织为辅助；参考专业媒体工具的素材分类和音轨表达，但首版保持基础音轨面板。具体布局、明暗主题、密度和控件尺寸需通过视觉草图讨论。

视觉候选方向、参考链接与边界详见 [前后端及视觉讨论稿](frontend-backend-visual.md)。参考产品不等于复制其代码、商标或资源，也不意味着纳入其全部功能。

## 14. 验证与交付要求

- 核心规则：命令校验、引用完整性、撤销重做、重复请求和版本冲突测试。
- 工程数据：保存重开一致性、素材路径与缺失提示、损坏文件恢复边界。
- 桌面集成：通过真实 Electron 窗口验证选文件、导入、编辑、预览和重新打开；浏览器单测不能替代此项。
- 音画表现：使用实际样本验证格式、图层显示、转场、进页/离页/暂停后的播放和资源释放。
- AI 协作：至少一个外部宿主真实调用，检查界面更新、继续编辑及撤销；协议模拟通过不能替代真实接入。
- 视觉验收：检查普通桌面尺寸与系统缩放下的画布、面板、焦点和错误状态，记录实际验证环境。

每阶段交付可运行成果、验证证据及已知限制；目前仅规划文档完成，所有运行验收均未执行。

## 15. 非线性流程与工作区建议

用户确认流程包含分支、循环等复杂连接；首版不再以线性链为模型。页面节点仍代表页面，当前不引入条件或对话作为额外节点类型。

建议以 pageId、edgeId、sourcePageId、targetPageId 表达连接，边可有名称和顺序用于辨识，但列表顺序不能自动决定分支选择。回到已有页面引用同一 pageId，不复制页面。流程图坐标属于编排布局，独立于页面内容。

主方案为双工作区：流程工作区显示整图、页面缩略图、连接及路径检查；单页工作区参考 PPTist/Penpot，显示该页图层、媒体、动画与画布。共享同一工程及撤销历史，切换视图不触发额外工程副本。双击节点进入编辑，“返回流程”恢复视口并定位原节点；可选的邻接页入口只作导航，不展开整张流程图。

复杂图首版建议有缩放、平移、小地图、搜索和高亮当前页相邻连接；节点只显示缩略图、名称及必要状态。自动排版、章节折叠和路径筛选按实测复杂度后续引入，不能按无环图限制真实循环。

连接结构与播放规则分开：多条出线需定义由用户选择、点击区域、条件还是其他事件决定；原有对话/选项细节暂缓讨论仍然有效。可先建议编辑态提供“选择本次预览路径”，用于检查图，但其不能替代最终阅读行为的验收。

循环本身合法。建议检查目标不存在、无起点、不可达页面等结构问题；若存在自动跳转，应单独检测不会等待用户或媒体的连续自动循环，避免播放器卡住。退出预览始终可用；循环内有用户动作的场景不能因重复访问而直接判错。

技术数据模型采用有向图而不是页码排序或单 nextPageId；遍历和可达性检查使用 visited 集合，路径预览可以重复访问页面。核心需验证分支、汇合、回连、删除节点与撤销恢复连接、保存重开，AI 接口使用相同图规则。
