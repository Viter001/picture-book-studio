# 产品全局设计与发展规划 v0.1

2026-10-27。本文承接此前产品规划 v0.5 的全局内容，讨论产品长期目标、架构边界与发展方向，不定义 MVP 必须实现的功能。
用户已要求全局设计与 MVP 分离。首版交付唯一入口为 [MVP 规划](product-plan-mvp.md)，其中仍需区分建议与已批准项；本文件中的长期方向不得自动变成首版验收条件。

## 1. 产品目标与已确认方向

产品源于绘本项目，但使用者可能制作绘本、Galgame、其他交互叙事作品；作品可能以网页或可分发程序交付，也可能由外部 agent 为用户制作。最终用户用途保持开放。

已确定编辑工具采用 Electron + React + 自有绘本模型。用户通过界面编辑，外部 AI agent 通过接口操作；软件内部不内置 AI 助手。主流图片、音频、视频接入，页面流程、图层显示、音频管理、类似 PPT 的动画/转场属于已提出的产品方向，具体版本分配另定。

流程节点目前指页面，长期流程包含分支、汇合和循环。用户指出复杂流程与单页编辑常驻同屏会拥挤；双工作区是建议方案，导航和视觉尚未定稿。

隐藏数值、选择改变数值并影响后续选项是待研究方向。Galgame 是可能用途，不意味着其全部功能已获批准，也不将产品扩展成未定义的通用游戏引擎。

## 3. 全局能力地图

| 方向 | 长期能力 | 需要继续设计的事项 |
| --- | --- | --- |
| 页面制作 | 页面、素材、图层、排版、文字与音画组合 | 基础对象、编辑行为、图层可见性语义 |
| 流程编排 | 分支、汇合、循环、路径检查、章节与局部图 | 出口触发、条件、返回与重访、图规模管理 |
| 音频与动画 | 背景/人物音轨、动作预设、转场、触发与同步 | 时间轴需求、跨页音频、循环和重播 |
| 故事状态 | 隐藏数值、标记、条件开放选项及选择效果 | 初值、重复计分、回退、存档、作者调试 |
| 外部 AI 作者 | 读取、编辑、校验、预览和生成作品 | 工具范围、宿主接入、失败反馈与编辑冲突 |
| 作品规范 | 可编辑工程、运行数据、素材、版本与兼容 | 格式契约、校验、迁移和能力声明 |
| 发布与运行 | 网页、离线程序或播放器文件 | 目标适配、媒体兼容、存档与分发 |

每个方向的具体深度都需以真实制作场景推进，不设未经确认的发布日期和版本号承诺。

## 4. 架构空间：保留边界，不提前建设全部能力

| 未来需要 | 现在建议保留的边界 | 暂不因此实现 |
| --- | --- | --- |
| 非线性流程 | 稳定页面 ID 与独立连接集合，内容顺序不等于播放逻辑；不把模型限制成只有一个 nextPageId | 完整分支条件 UI、循环规则、复杂自动布局 |
| 隐藏数值和条件 | 播放状态与作品定义分离；连接模型可按版本增加条件/效果；规则执行与画面渲染分离 | 公式语言、变量编辑器、调试器或空壳规则系统 |
| 外部 agent | 编辑逻辑通过可调用命令进入，共用校验与错误结果，不埋在按钮事件中 | 覆盖全部功能的工具集合、后台 agent、内置聊天 |
| 多种导出 | 内容模型与 Electron API 分离；播放逻辑独立于发布壳 | 同时完成网页/桌面/移动端导出及通用插件平台 |
| 更多媒体与动画 | 素材 ID、相对引用、明确类型；动画预设 ID 与参数分离 | 完整格式转码、复杂剪辑器和大量动画库 |
| 作品演进 | 格式版本、稳定 ID、校验与明确的不支持提示 | 全历史格式迁移和任意未来字段兼容 |

预留不等于创建所有未来字段、占位模块或抽象框架。只实现当前功能需要的结构，后续通过有版本的格式演进添加能力；遇到不支持的版本不能静默删字段再保存。

“场景”可作为未来的抽象命名候选，但用户未要求现在决定。当前讨论仍以页面/节点为主，不因长期用途强制改名或修改首版交互。

## 5. 前后端与工程职责（建议）

- React 前端：编辑交互、流程/页面视图、属性和素材展示、预览；维护临时选择及拖拽反馈。
- Electron preload：明确的操作接口与事件桥接，避免把任意文件写入暴露给界面。
- 本地应用服务：工程状态、文件与素材、命令校验、撤销及变更通知；多个入口共用一个写入者。
- 共用核心：工程类型、引用规则、校验和编辑命令；不依赖具体 UI。
- 播放模块：页面渲染、媒体生命周期及状态推进；预览和未来运行包共用语义。
- agent bridge：将对外工具映射到同一命令服务，不维护第二份工程。

TypeScript、React Flow、Moveable、MCP 是调研后的建议组件，版本和边界在正式设计中确定。耗时媒体处理与轻量工程提交分离；首版采用本地服务不要求云端账号或远程数据库。

工程类型建议包含 Project、Asset、Page、Layer、Connection、AudioTrack 和动画配置；定义格式版本及资源引用，编辑布局与作品内容区分。命令建议携带工程标识、请求 ID 与版本，支持可解释的失败和状态更新。具体 API 不在本轮冻结。

## 6. 工作区与复杂流程（建议）

流程工作区负责全图、连接及路径检查，单页工作区参考 PPTist/Penpot，负责画布、图层、媒体和动画。节点进入页面，返回时恢复流程位置与缩放；多个页面标签可后续补充。详细候选见 [视觉讨论稿](frontend-backend-visual.md)。

复杂流程的连接结构和实际播放语义需分开设计。多个出口由什么决定、循环能否重复计分、返回是否回滚状态、无可用出口怎么办，需要在相应能力进入版本前确定。

循环本身合法；结构检查应关注不存在的目标、不可达内容等问题，自动跳转无等待的循环另行处理。遍历不得因回连无限运行，编辑态选择预览路线不能冒充已实现真实分支规则。

## 7. 作品标准与发布方向

建议分离编辑工程、可运行作品数据、播放核心和目标封装。人工与 agent 生成的工程遵循相同格式；读者存档与作品初值分离。不同发布目标要求相同规则表现，但媒体、加载和存储适配仍需分别实测。

可编辑工程要能保存、迁移和重新编辑；运行包根据目标收集素材与播放器。文件名、压缩形式和扩展名尚未确定。工程中未完成的图可存为草稿，发布需更严格校验。

多目标交付是全局方向，当前无需唯一选定网页或桌面。各导出器何时实现由版本规划决定；进入某个版本前再确定该目标的具体验收。详见 [产物规范讨论草案](artifact-standard-draft.md)。

## 8. 发展阶段：候选主题，不是排期承诺

| 阶段主题 | 预期解决的问题 | 进入阶段的依据 |
| --- | --- | --- |
| MVP：基础可视化制作 | 用户能够手动完成最小制作与保存 | 独立 MVP 范围与验收先确定 |
| 制作效率 | 图层、素材、音轨、效果与流程编辑更顺畅 | 首版真实制作反馈 |
| 叙事逻辑 | 分支循环的完整运行、条件与隐藏状态等 | 剧情样本与规则明确、核心模型可承载 |
| 作品交付 | 规范运行包、目标适配与迁移 | 明确第一个发布场景和验收环境 |
| 扩展用途与 AI 工作流 | Galgame 样本、更多自动化制作能力 | 已有核心验证有效，再评估新增能力 |

这些主题可能交叉推进，顺序可以调整。不能从此表推定“所有分支功能必须很晚做”，也不能反推“全局已提到就必须首版做”。
