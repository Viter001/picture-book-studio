# 终端 UI 接入计划

**目标：**将用户认可的 v2 终端样稿方向接入现有 Electron 编辑器，保持现有业务能力。
**架构：**沿用 React 双工作区、现有命令与存储；样式由 Codex 调整，功能区及退出确认逻辑由 DSH 实现。无新增依赖。
**依据：**docs/product-roadmap.md 的第二轮 UI 方案，docs/prototypes/ui-direction-v2.html；用户本轮明确“接入吧”。

## 范围和约束

- 墨黑 #0d0f0e、灰绿 #c5d0c0、酸黄 #dfff00、信号绿 #4ec97a，薄边、弱化体素阴影；作品内容不改色、不像素化。
- 保留原有曲线与连接行为，暂不实施前进／循环／后退分类，不按分支随机分色。
- 设置菜单仅加入产品规划，内容、位置与版本待定，不创建虚假功能入口。
- 保留用户 QUESTIONS.md 改动与原始反馈，工人不得提交或回退他人文件。
- 生产保持沙箱与隔离；普通目录启动验证，不能把诊断用无沙箱当默认交付。

## 执行步骤

- [x] DSH：src/ui/App.tsx 添加真实文件／开始／插入／视图功能区及工作区切换，绑定已有操作；保证旧能力均可访问，测试据真实界面调整。
- [x] DSH：src/electron/main.ts、preload.ts、src/ui/api.ts 与 App 的必要接口实现主题内未保存确认；保留焦点输入 flush，取消／丢弃／保存成功才退出，保存失败与重入不丢数据；覆盖实际回归。
- [x] Codex：src/ui/style.css 统一现有布局与新控件样式，压缩顶栏、清晰焦点和状态、深色 React Flow；不写 DSH 所有文件。
- [x] 集成：类型、核心测试、构建、受影响 Electron 回归与截图；检查长名称、无工程、缩放、保存失败、焦点尚未提交的输入。
- [x] 交付：打包，提供可启动的新版入口，更新规划、验收、反馈、讨论与开发记录，本地中文提交。

## 验收重点

新建/打开/撤销/保存/导入/预览不因菜单分组丢失；无工程和无选中页面时禁用正确；切换页面与流程保持数据；编辑器深色不污染作品；未保存退出可取消且失败不关闭；用户复验状态不由代理检查替代。

2026-10-30 接手说明：Codex 额度耗尽后由 DSH 核对并集成其未提交样式与 DSH 工人成果；补齐命令标签语义、深色窗口底色、保存失败可读提示和测试脚本对外部普通目录 EXE 的支持。
